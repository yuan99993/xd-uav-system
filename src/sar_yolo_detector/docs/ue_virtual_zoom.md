# UE 虚拟镜头与视场角验收

正式入口默认固定水平视场角 90°。第 3 阶段持续图像通道验收后才加入本项；没有自动目标驱动变焦。

## 显式开启受控镜头

```bash
roslaunch sar_yolo_detector ue_dfine_v3_live.launch \
  ue_project:=/mnt/d/UE/Project/pro1 pose_source:=kinematic \
  allow_fov_control:=true
```

向 `/ue_test/camera/fov_target_deg` 发布 `std_msgs/Float64`，单位为度。默认不注册此控制订阅；开启后才接受指令。合法目标范围 45–100°，实际响应受 8°/s 转速和 16°/s² 加速度限制，非有限数或越界指令被拒绝。目标值保持到下一条合法指令；发送 90° 返回默认视场角。

```bash
rostopic pub -1 /ue_test/camera/fov_target_deg std_msgs/Float64 'data: 60.0'
rostopic pub -1 /ue_test/camera/fov_target_deg std_msgs/Float64 'data: 90.0'
```

也可以显式使用 `fov_profile:=zoom_test`：启动后 8 秒请求 60°，20 秒请求 90°，执行器仍按上述限制响应。`fov_profile` 还可指向 JSON 文件：

```json
{"schedule": [[0,90], [8,60], [20,90]], "actuator": {"max_rate_deg_s": 8, "max_accel_deg_s2": 16}}
```

若同时开启 ROS 控制，最新合法 ROS 目标覆盖时间表。运行时镜头指令便于在算法准备好、目标居中后开始重复测试。停止取流后恢复 90°。该功能改变 UE 虚拟透视镜头的视场角，没有对真实光学变焦硬件作出假设。

## 同步的数据与算法

- 每帧从 UE SceneCaptureComponent2D 读取实际 FOV，连同原始采集时间、实际相机姿态和尺寸固定在帧元数据中。
- Image、CameraInfo 与 TF 同采集时间/光学坐标系；`fx=fy=width/(2*tan(hfov/2))`，主点位于图像中心。
- SAR 按原帧时间、坐标系和尺寸缓存相机内参，保留 256 个标定样本。迟到图像使用自己的 K；动态相机不回退使用最新或旧静态 K。
- 在同一世界坐标系中，若两个采集时刻测得的光心位置相同，可使用对任意场景深度均成立的纯旋转/镜头变换；背景估计仍执行并单独报告是否有效。有真实平移时继续使用原验证流程，不作无深度的精确投影假设。
- 相机旋转/镜头补偿使用 `K_current * R_current.T * R_previous * inverse(K_previous)`。缺失配对时不假装沿用固定焦距，仍可使用通过验证的背景运动估计。
- 选定窗口持续携带四边形像素支持区域；只有投影到当前帧后才取外接框。像素测量的平移/尺度修正作用于该支持区域，既避免累计膨胀，也保留真实旋转后的长宽变化。
- KCF 重建后先在初始化画面完成首次模型更新，再在当前画面测量目标自身的位移；预热不产生额外观测或控制消息。独立目标运动叠加连续镜头补偿的回归须通过，避免只有相机在变、目标不动的测试漏掉问题。
- 变焦即使每帧小于 3 像素，也更新选定目标的局部模板；模板来自经过几何变换的前一原始画面，不用当前框自证。保留 KCF 整数初始化产生的亚像素余量，避免小尺度变化每帧被取整丢失。
- Fusion 的颜色模板使用自身上一次原帧到当前帧的完整变换，颜色参考面积、窗口尺度、锚定面积和残余速度同步传播。
- 外观参考按 ROI 周围背景的对比度加权，避免“只取有颜色像素”或“框中心就是目标”的假设把黑车排除、反而学习草地；HS 与亮度联合、相邻量化箱平滑，降低变焦重采样的假性外观突变。草地、黑车、白车及偏心 ROI 的排斥回归仍需通过。
- LK 对新检测包传播失败时，只有原帧 Smart 身份已接受、当前同一 ID 仍被局部视觉可靠观测、两端标定和完整相机变换可用，才提出几何交接候选。候选还必须通过更严格的当前特征分数≥0.85、IoU≥0.60 等验证；不重绑定/恢复身份，不采用投影坐标作为测量，不重写检测时间。LK 依旧执行并记录失败。
- 四模式、D-FINE-S V3、BoT-SORT/Smart 身份裁决、颜色/特征/LK 证据和 SAR→XD 输出保持原流程。尺度、身份、时效和相似度门限未放宽，预测框不能刷新云台控制。

CameraInfo 同步传递给现有 ROS 使用者；当前 XD 感知链路接收带原帧尺寸的像素观测。本项不启用额外飞行制导或替代 PX4 的动力学。

## 真实 UE 验收

使用包内 `config/ue/gimbal_acceptance_scene.json` 可重复进行运动学悬停、运动目标测试，先启动上述带 FOV 控制的正式入口，再运行：

```bash
rosrun sar_yolo_detector verify_ue_zoom.py --namespace ue_test \
  --web-url http://127.0.0.1:8787 --output /tmp/ue_zoom_acceptance
```

脚本从网页选择真实检测目标，居中后执行 90→60→90，保存三个视场角的图像、逐原帧标定、有效测量、Fusion 证据和实际算法调用计数。每一段锁定率均须≥75%，选定公共 ID 不变，至少 95% 的当前测量具有同原帧标定，中心误差 p95<0.18，镜头模板/颜色尺度更新均必须实际执行。脚本不发布替代图像或目标真值。

`camera_calibration_update`、`fusion_lens_template_refresh`、`fusion_color_lens_update`、`manual_lens_template_refresh` 出现在原有 pipeline_trace 中。变焦期间拒绝/失锁仍按真实数据报告，不把模型漏检改记为成功锁定。

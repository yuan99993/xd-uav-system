范围：仅实验工作区 SAR 包；正式工作区未改，实验 XD 包对远程导出基线的 rsync 校验无差异。
train7.pt SHA-256 保持 `8f2506e1fd9585eab0d23203f504ff0036d580327e55ef15d23bd9e46fd34b54`。

## 原因与修复

原车辆配置没有启用跨类别 NMS，tank/m142 等类别的重叠候选可以各自产生 BoT-SORT ID。
融合节点只按选中公共/局部 ID 替换框，其他 ID 的冲突框仍会被输出。

现在车辆配置启用模型前端 class-agnostic NMS（IoU=0.60），在轨迹分配前抑制重复候选。
融合节点对原帧候选及最终结果补充保守的同父组异子类去重：IoU>=0.75，中心差不超过较小框宽高的20%。
优先保留新鲜、已验证的选中目标；其他重复候选优先置信度。缓存、数值输出和叠框使用相同结果。
不修改 ROS 消息/服务；不合并两条轨迹的身份档案；不取消新 ID 的连续重获确认。

## 验证

- Python 回归 72 项通过，含真实 OpenCV KCF、相邻车辆保留、重复框原帧 ROI 选择、选中 ID 保持、弱观测语义及重获确认。
- install 构建通过（`-j1 -l1`）。
- 实际 Gazebo/CUDA/PT 45.02 秒：176 帧检测输出、异类高度重合帧 0、重复数值 ID 帧 0。
- 选中 ID 始终为 1；fused 87 帧、YOLO 4 帧、ambiguous 5 帧、lost 78 帧、未选中 2 帧。
- 165 个有效定位候选；原图及叠框均为 640×480；处理 P95 84.85 ms。
- 融合后端抑制计数为 0：本轮未捕获需后端补救的重复框，不能据此推算 YOLO 内部 NMS 删除量。

## 限制

此为联通与重复框专项验证，不是带真值的识别精度/身份正确率验收。
场景仍运行全局搜索，选中 SAR 目标不会自动让飞行驱动跟随，目标出画后会发布 lost，不能当成持续锁定成功。
本轮 P95 不能与不同运行时段的旧报告直接组成速度 A/B；没有声称推理变快或检测召回提高。

类别去重不能判断哪个类别才正确；非常接近且大幅遮挡的两辆车也可能被 NMS 抑制。
只有位置接近不足以合并，仍需实拍/UE 录像的交叉遮挡验证。
UE 应另外核对图像分辨率/色彩、压缩、相机时间戳、目标像素尺寸，以及带人工标注数据上的类别混淆、召回、ID switch。
不应以美术细节或本轮无重复框推断 UE 部署效果。当前没有修改模型、地图或 YOLO 类别合同。

# 融合模式整帧连续输出修正

日期：2026-10-06。

原因：选中目标的 SOT 在每张图像到达时输出，但该帧完整检测/关联尚未到达。
原实现按严格同帧规则得到空的普通目标列表，发布 SOT-only 画面；检测到达后
再发布完整场景，造成未选中目标闪烁。这不是目标身份真的被删除。

修正：fusion 与 detect 一样按完整检测/关联快照提交画面；选中目标仍逐图运行
局部跟踪，在对应采集时刻的快照中替换其框，不把旧帧框复制成新实测。
track 模式仍可独立按 SOT 更新输出。停止的相机仍可发出清空/失联状态。
detect/fusion 的各来源使用 discovery 帧率，不因选择目标改用 standby 降频。

没有更改 YOLO 权重、身份门控、像素辅助算法或 LOST/PRED 安全语义。
代价是融合画面的提交频率与完整检测场景一致，不保证达到 SOT 内部更新频率。
真实漏检、遮挡和出画仍需如实显示预测或丢失，不能承诺永不消失。

第二轮排查：正常检测校验也会重新初始化 CSRT 并回放缓存，而且持有模式管理器
公共锁。现在通过外观/运动/歧义门控、SOT 正常且 IoU ≥ 0.5 时只校验和更新
对应帧实测及类别信息，不重建跟踪器；失败、冲突或明显偏离时仍允许重建恢复。
OpenCV 工作线程默认限制为 1（`~opencv_threads` 可设 1–4），防止线程池争抢。
并未以降低类别/歧义门控或永久保留旧框换取显示连续性。
第二轮模式、失锁显示、定位元数据共 25 项回归通过，其中明确测试正常匹配不得
初始化/回放，以及失败后必须可以重新初始化。实际联调视觉稳定性仍需场景观察。

第三轮直接对照记录发现：RAW 始终包含 ID 1/4/5，但 OUT 在仅 ID 4 与三个 ID
之间交替。运行进程指向 install，里面的脚本仍是旧版本，前两轮运行结果不能
作为修改后性能证据。`catkin_install_python` 安装的是 configure 阶段生成的
`catkin_generated/installspace` 快照；只执行 `cmake --install` 不会重新生成它。
修改 Python 节点后须重新配置（例如正确 ROS 环境下 `catkin build --force-cmake`）
再安装，并在重启前核对源码与安装脚本内容，允许首行 shebang 差异。
不是 rosbridge 反复断开连接，也不是底层三条轨迹被删除。

重新配置、安装并校验后，安装脚本（排除 shebang）SHA-256：

- mode manager：`3d3fd87951772cd2c54a24c1b2dea64a102d75272aeb56d8da23eaa9e17873ec`
- shared detector：`23afbbcbfc2c40e16dba5b5e2f3553a1e3b9caef9b968facfcc9ab7de326b119`

正确版本实际联调：fusion 选中 ID 4，10 秒内收到 19 个目标快照和 19 个网页
视频帧，全部含 3 个目标；19 个对应底层快照均无缺失目标，网页视频也无缺失。
最大目标输出间隔 0.792 s。这证明本次低负载片段中的整帧清空冲突消失，
不代表高帧率流畅性、所有遮挡场景或实机精度已经通过。当前演示有意限制推理
频率，约 2 FPS 的场景提交仍有低帧率观感，不能把提高帧率与身份正确混为一谈。

回归：模式测试 13 项、共享检测调度测试 8 项、丢失显示/定位元数据测试 11 项通过。

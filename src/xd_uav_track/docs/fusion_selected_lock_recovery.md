# Fusion 选中目标的连续性与自动恢复

更新日期：2026-10-06。仅修改 tracker 模式管理层及其测试；保持 train7
识别模型、公开 ID 分配、类别合同、叠框标签、坐标与现有输出接口不变。

## 修正的逻辑

1. 同一采集帧、同一公开身份仍有 confirmed 检测或视觉辅助观测时，
   不允许失效 SOT 的 stale 框覆盖它。真实身份冲突仍禁止这个替代路径。
   运行状态依据有时限的最终选中观测更新，不因单个局部算法失败就取消选择。
2. 原始检测框与 Kalman 平滑框用途分离：检测校验和 SOT 重初始化使用
   同帧原始、已关联 ID 的测量几何。平滑框不是当前检测器的独立位置证据。
   原始锚点迟于轨迹消息到达时，可以补做此前失败的校验。
3. 光流历史按来源保存，长度受图像缓存上限约束。YOLO 迟到时，取它的
   **采集时刻**光流快照，不把“最新帧没有对应证据”当作历史帧的失锁。
   模式/模型切换和时间段重置清理历史，不能跨 epoch 使用。
4. 已有 ID 的失败 SOT 可用同帧可靠光流 + 高置信检测自动重建；不分配
   新 ID、不寻找最近的另一辆车。不使用预测框、低质量光流、别的来源或
   该帧刚由 YOLO 初始化的光流作为独立恢复证据。
5. 两个有效视觉观测一致、只有检测修正偏离时，拒绝该次检测修正而不是
   强制停掉两个跟踪器。前置的最佳/次佳候选歧义门控仍生效；没有双观测
  一致性时不采用此双观测例外，也不更新长期外观。另一个保守路径只允许
  当前采集帧的有效 SOT、可信参考外观及无身份歧义时继续输出，拒绝几何
  检测修正，而不是撤销当前真实观测；若存在 LK，则还须与其一致。
6. 外观参考只在身份、位置和歧义校验通过后做小步归一化更新，避免永远
   对照最初车头朝向；被拒绝的图像不能污染参考。健康 SOT 不逐次重建。

## 安全边界

- 不保证完全遮挡或出画时仍有真实框；不把旧框、预测位置标成新实测。
- 不因选中目标消失就自动选择另一公开 ID。重新出现仍需证据与门控。
- 所选目标的选择状态与“当前可以确认位置”不同。保留选择不代表允许
  下游使用过期三维位置。
- 没有改变新轨迹置信度 0.50、外观门控或已有多目标关联算法的全局门限。
- 本次连续性探针只计算选中公开 UID 的输出存在情况，不能证明真实 ID
  始终正确，也不等同于带真值可见性标注的 HOTA/IDF1 验收。

## 视频逐次更新复查与统计口径纠正

用户反馈转弯仍闪框。旧探针对相同采集时间只统计第一次消息，忽略了后续
同帧修订，也没订阅视频。因此旧报告的 325/325 只能说明首次目标快照
有框，**不能证明网页持续有框**，不得用这个比例单独放行。

`measure_fusion_lock.py` 的 schema_version=2 保留旧字段作对照，新增
`target_revisions` / `video_revisions`：统计每次更新、同帧从有效变丢失、
保留窗口内每个采集帧的最终状态及最早 32 次缺失。窗口最多 600 帧。
只有这些新增字段及实际视频检查可以用于本次闪框复查；旧顶层 `frames`
和 `observed` 仍是首次快照口径。`draw_checks` 对靠近顶部状态栏的选中框
额外检查 PNG 中的绿色像素，不解码所有视频帧以增加持续负载。

复查先保留用户选择 ID 3 做 70 秒只读采样，记录在
`logs/fusion_video_revisions_before_fix.json`：449 次目标更新中有 1 次
stale/LOST，随后同帧恢复；208 次视频更新中未捕捉到缺框。说明瞬时异常
是否可见受编码时机影响，该短段不能反证用户反馈。

进一步修正：

- 单独保留一个当前帧的原始 SOT 结果，避免已拒绝检测所留下的 lost 状态
  污染下一帧独立观测。只有**几何冲突**且当前 SOT / 高质量历史锚定 LK
  同 ID、同帧、无竞争目标、位置和外观一致时才恢复。appearance_conflict
  和 ambiguous_competitor 不允许借此绕过。
- 状态栏先绘制，再绘制目标框，避免顶部 28/50 像素的有效框被状态栏背景
  覆盖；不改变目标坐标，不显示旧框，不修改类别/ID标签。
- 新增同帧修订计数、缓存上限、几何拒绝后的连续恢复、歧义不绕过和
  顶边框真实绘制像素的单元测试。

修正后的网页/视频采样记录为 `logs/fusion_video_revisions_after_fix.json`，
以该文件的逐次更新与视频字段为准。完整遮挡仍应输出 LOST，不以旧框
留在屏幕上掩盖失锁。

该次 120 秒复测实际仍失败：354 次视频更新中 33 次缺框，首次快照口径
最长缺失段 8.54 秒，不能把“做了修正”描述为“已解决”。进一步修正
同一采集帧的几何比较：零时间差不是跨帧速度，不使用 12 像素移动门限；
改为严格同帧重叠、尺寸和外观校验，跨帧时间门控保留。
同一全局身份的两次新鲜、低协方差 FRD 定位可以支持局部跟踪重建，
不会用附近新 ID 代替原身份。重复采集时间不能计作两次确认。

随后 `logs/fusion_video_metric_recovery.json` 也是未通过：357 次视频更新
中仍有 19 次缺框，目标消息出现 17 次同帧有效到 LOST 的降级。该次选择
ID 4，上一轮是 ID 3，且路线起点不同，不能据此作同目标 A/B 改善结论。
因此补充了上文“拒绝异常几何修正、保留当前已验证 SOT”的路径。
最终实测使用 `logs/fusion_video_geometry_continuation.json`；以其实际内容
判定，不以单元测试替代视频验收。

上述几何连续性修正的 120.065 秒实测：固定相机所选 ID 1，758 次目标
更新、355 次视频更新中缺框均为 0，同帧降级 0；首次快照 425/425 有效，
最大有效观测更新间隔 0.50 秒。观测为 detector / visual_tracker，未以
预测替代实测，也未重新选择。它是该次场景的连续性记录，不是多目标
真值身份准确率或全场景零丢框保证。

追加安全修正保持身份冲突状态：后续几何拒绝不能将此前的
ambiguous_competitor / appearance_conflict / appearance_unavailable
改写成可由视觉一致性清除的几何状态；重复帧及 LK 同意也不能绕过。
最终版本重新启动后的记录另存为
`logs/fusion_video_final_guard.json`，不覆盖前一版本的 120 秒结果。

最终版本补测 90.028 秒：固定相机选中 ID 1，579 次目标更新、268 次视频
更新，缺框及同帧降级均为 0；325 个首次快照均为有效 visual_tracker
观测，最大更新间隔 0.50 秒，无预测替代和人工重新选择。此次只证明
已订阅视频快照中该选中身份框的连续性，不证明框与真值的 IoU、长遮挡
重识别、云台全部姿态或长期性能已经验收。

## 云台选中目标闪框：2026-10-07 后续整改

不更换 train7 TensorRT 模型、检测门限或飞行策略，整改内容为：

- 中间光流帧选中已有 ID 时，以缓存中的真实同源检测绑定身份观察器；
  同采集时间光流不覆盖真实检测档案，受控重试限频且最多四个锚点。
- 同帧 YOLO 漏检/预测不抹掉质量合格的独立 LK 观测；CSRT 失败时可
  用同 ID 当前视觉观测补位，不能越过身份歧义或拿历史框冒充实测。
- 迟到 LK 到达时重新裁决当前检测帧；不重复计算身份确认次数。
- 全局世界位置及协方差使用采集时刻姿态，旧保留定位不重新计为新定位。
- 新 ID 拼接仍需三次唯一检测确认；短间断内已启动的同候选确认允许
  在有界连续窗口内完成，长失联、候选改变、世界创新/外观冲突仍拒绝。
- 身份服务使用原始同帧 YOLO 框和置信度，不用 Kalman/EMA 表示身份
  证据。原始 0.20 的检测不借旧高 EMA 过关；原始高分检测也不因低
  EMA 延迟确认。新增实际 ROS 用例同时验证这两条及三帧门槛保留。
